# Automated Through-Transmission Waveform and Temperature Acquisition in LabVIEW

## Project Purpose

This LabVIEW program was developed to automate data collection for a **through-transmission ultrasonic measurement setup**.

The setup uses oscilloscopes to record ultrasonic waveforms while temperature is measured at the same time. The program is intended to support repeated measurements over time without requiring a user to manually save each waveform.

The current implementation uses:

- two MDO32 oscilloscopes;
- two waveform channels from each oscilloscope;
- four total waveform channels; and
- a cDAQ temperature measurement.

The program repeatedly saves the acquired oscilloscope waveforms and records temperature information so that waveform behavior can later be examined together with the temperature history of the experiment.

This is especially useful for long-duration testing, where a large number of repeated waveform measurements may need to be collected over time.

---

# Main Program

The main VI is:

`MDO32_2-2-Channel_V2.vi`

The program handles:

- communication with two oscilloscopes;
- acquisition from two channels on each oscilloscope;
- saving four waveform files during each iteration;
- collection of temperature data;
- timestamping of the test;
- repeated automated acquisition;
- status indication for each saved waveform;
- tracking of the current iteration; and
- controlled shutdown after testing is complete.

# General Program Workflow

At a high level, the program performs the following sequence:

```text
Start Test
    |
    v
Initialize Test Information
    |
    v
Read / Record Temperature
    |
    v
Oscilloscope 1
    |-- Save CH1 Waveform
    |-- Save CH2 Waveform
    |
    v
Oscilloscope 2
    |-- Save CH1 Waveform
    |-- Save CH2 Waveform
    |
    v
Confirm Four Samples Saved
    |
    v
Wait for Configured Delay
    |
    v
Increment Iteration
    |
    v
Repeat Until Stop Is Requested
```

This allows repeated through-transmission waveforms and temperature measurements to be collected automatically over time.

# Channel Mapping

The program saves four waveform channels.

The channel mapping in the current VI is:

| Saved Channel | Oscilloscope | Oscilloscope Channel | Saved Filename Pattern |
|---|---|---|---|
| Channel 1 | MDO32_1 | CH1 | `waveform_ch1_%d.isf` |
| Channel 2 | MDO32_1 | CH2 | `waveform_ch2_%d.isf` |
| Channel 3 | MDO32_2 | CH1 | `waveform_ch3_%d.isf` |
| Channel 4 | MDO32_2 | CH2 | `waveform_ch4_%d.isf` |

The `%d` portion of each filename is replaced by the iteration number.

This provides a sequence of waveform files for each channel across the duration of the test.

---

# Waveform File Format

The program configures the oscilloscopes to save waveforms using the internal Tektronix waveform format:

```text
ISF
```

The block diagram includes the command:

```text
SAVE:WAVEFORM:FILEFORMAT INTERNAL ISF
```

Each saved waveform is therefore stored as an `.isf` file.

These files contain the waveform information generated by the oscilloscope and can later be imported or processed for ultrasonic analysis.

## `Wait Time (s)`

Controls the delay between repeated acquisition iterations.

The current default shown on the front panel is:

```text
10 s
```

This value determines how frequently the program repeats the waveform-saving sequence.

For example, a wait time of 10 seconds produces repeated acquisitions separated by approximately that delay, in addition to the time required for the waveform-save operations themselves.

Changing this value changes the time resolution of the long-duration dataset.

# Oscilloscope Save Sequence

For each waveform channel, the program selects the desired source channel and sends a save command to the corresponding oscilloscope.

The command pattern includes:

```text
DATA:SOURCE CH1
```

or:

```text
DATA:SOURCE CH2
```

followed by waveform save commands.

The current filename patterns are:

```text
waveform_ch1_%d.isf
waveform_ch2_%d.isf
waveform_ch3_%d.isf
waveform_ch4_%d.isf
```

The program also uses:

```text
*WAI
```

commands to make the instrument wait for operations to complete before continuing.

This is important because saving waveform files to the oscilloscope USB drive takes time.

# Through-Transmission Measurement Context

This VI is part of a through-transmission ultrasonic setup.

In a through-transmission experiment, the recorded waveform represents the transmitted ultrasonic response collected by the measurement system.

The purpose of this program is not to perform the later ultrasonic analysis directly. Its role is to automate the **data acquisition and saving** stage.

The resulting waveform files can later be analyzed for quantities of interest using separate processing tools or scripts.

Because temperature is collected during the same test, the waveform data can also be examined together with temperature changes when that relationship is relevant to the experiment.

# Running a Test

A recommended operating procedure is:

1. Confirm that both oscilloscopes are powered on.
2. Confirm that the cDAQ temperature hardware is connected.
3. Insert **USB 1 into Oscilloscope 1**.
4. Insert **USB 2 into Oscilloscope 2**.
5. Open `MDO32_2-2-Channel_V2.vi`.
6. Verify `MDO32_1`.
7. Verify `MDO32_2`.
8. Verify `cDAQ1Mod1`.
9. Enter a descriptive `Test Name`.
10. Confirm the file path.
11. Set the desired `Wait Time (s)`.
12. Start the VI.
13. Confirm that `Iteration Running` becomes active.
14. Confirm that Samples 1–4 are being saved.
15. Confirm that the iteration number increases.
16. Allow the program to continue for the desired test duration.
17. When testing is complete, click `Stop` **once**.
18. Wait for the program to finish the required remaining iterations before closing LabVIEW.

# Stopping the Program

The front panel contains an important warning:

```text
CLICK STOP BUTTON ONLY ONCE
```

The VI does not stop immediately.

The front panel notes that the loop must:

- complete the current iteration; and
- complete one additional full iteration

before the program stops.

This means the user should expect a delay after pressing `Stop`.

Do not repeatedly press the stop button.

Do not force-abort the VI unless absolutely necessary, because doing so may interrupt waveform saving or leave the current dataset incomplete.

# Data Organization

Each iteration produces up to four waveform files:

```text
waveform_ch1_<iteration>.isf
waveform_ch2_<iteration>.isf
waveform_ch3_<iteration>.isf
waveform_ch4_<iteration>.isf
```

Over a long-duration test, this creates a sequence of files for each channel.

For example:

```text
waveform_ch1_0.isf
waveform_ch1_1.isf
waveform_ch1_2.isf
...

waveform_ch2_0.isf
waveform_ch2_1.isf
waveform_ch2_2.isf
...
```

and similarly for Channels 3 and 4.

The iteration number allows waveform files from the same acquisition cycle to be associated with one another.

# Long-Duration Testing Considerations

## Verify Storage Before Starting

Repeated `.isf` waveform files can accumulate over time.

Before running a long experiment:

- estimate how many iterations will be collected;
- verify that both USB drives have adequate free space;
- verify that the intended test folder/location is correct; and
- confirm that previously collected data will not be overwritten.

---

## Check the First Few Iterations

Before leaving a test unattended, confirm that:

- all four `Sample Saved` indicators activate as expected;
- the iteration number increases;
- the temperature system is operating;
- both oscilloscopes are responding; and
- waveform files are actually appearing on the intended storage devices.

Do not rely only on the fact that the VI is still running.

---

## Keep Wait Time Consistent

If comparing measurements over time, changing the wait time during a test will change the acquisition spacing.

If a different interval is required, it is generally cleaner to stop the current dataset and begin a new test with the new setting.

---

## Keep Channel Connections Documented

The VI defines the electronic channel mapping, but students should also document what each physical ultrasonic channel corresponds to in the experimental setup.

For each test, record:

- transmitting transducer;
- receiving transducer;
- oscilloscope channel;
- physical sample location;
- temperature sensor association; and
- any other experimental configuration information needed to interpret the waveform later.

# Troubleshooting

## Program Gets Stuck

The front panel explicitly warns that this may occur when required devices are not connected or configured correctly.

Check:

- MDO32_1 connection;
- MDO32_2 connection;
- USB 1 in Oscilloscope 1;
- USB 2 in Oscilloscope 2;
- cDAQ connection;
- LabVIEW device selections; and
- oscilloscope communication.

---

## One Sample Does Not Save

Use the individual `Sample 1 Saved` through `Sample 4 Saved` indicators to identify which part of the sequence failed.

Then check the corresponding:

- oscilloscope;
- source channel;
- USB drive; and
- save path.

---

## No Temperature Data

Check:

- `cDAQ1Mod1`;
- cDAQ connection;
- DAQ configuration;
- temperature sensor wiring; and
- whether the DAQ task is returning an error.

---

## Iteration Number Does Not Increase

The program may be waiting for an oscilloscope save operation or another device operation to finish.

Check the sample-save indicators to identify where the current iteration stopped.

---

## Stop Button Appears Not to Work

This may be normal.

The VI is intentionally designed to finish:

1. the current iteration; and
2. one additional full iteration

before stopping.

Click `Stop` once and wait.

# Modifying the Program

## Preserve the Oscilloscope-to-Channel Mapping

The current mapping is:

```text
MDO32_1 CH1 -> waveform_ch1
MDO32_1 CH2 -> waveform_ch2
MDO32_2 CH1 -> waveform_ch3
MDO32_2 CH2 -> waveform_ch4
```

If the hardware configuration changes, update both the acquisition commands and the documentation so that saved filenames remain meaningful.

---

## Preserve the Save-Wait Sequence

The `*WAI` commands are important because oscilloscope file saving is not instantaneous.

Removing or bypassing these waits may cause later commands to execute before the previous waveform has finished saving.

---

## Be Careful When Changing the Stop Logic

The current stop sequence intentionally allows additional loop execution before termination.

If the shutdown behavior is modified, verify that:

- partially completed iterations are handled correctly;
- waveform files are not interrupted during saving;
- DAQ operations terminate correctly; and
- the program does not leave either oscilloscope waiting indefinitely.

---

## Keep Temperature and Waveform Timing Meaningful

The usefulness of collecting temperature and waveform data together depends on preserving their temporal relationship.

If the acquisition sequence is substantially modified, verify that the recorded temperature still corresponds meaningfully to the waveform iteration being analyzed.

# Suggested Workflow for Later Analysis

This VI is primarily an acquisition tool.

A typical later workflow may include:

1. Identify the waveform files belonging to a particular iteration.
2. Import the `.isf` waveform data.
3. Reconstruct the time-domain waveform.
4. Perform the desired ultrasonic analysis.
5. Associate the result with the corresponding iteration/time.
6. Compare the waveform-derived quantity with the measured temperature when relevant.
7. Examine how the transmitted ultrasonic response changes over the duration of the test.

The specific ultrasonic parameter to calculate depends on the experiment and is outside the scope of this acquisition VI.
